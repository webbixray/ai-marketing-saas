# Weekly Review Ritual

## Purpose
To sustain this project as an ongoing product rather than a one-off release, we institutionalize a lightweight but repeatable development cycle.

## Frequency
- **Weekly**: Backlog grooming and review
- **Daily**: Stand-ups focused on blockers
- **Bi-weekly**: Sprint reviews

## Weekly Review Process

### 1. AI Output Metrics Review
- Track AI output relevance scores (user ratings 1-5)
- Monitor hallucination rate (instances of incorrect/generated content)
- Log failed provider calls and failure modes
- Identify patterns in AI output decay

### 2. User Feedback Analysis
- Review user satisfaction scores
- Analyze feature usage analytics
- Capture bug reports and feature requests
- Review churn indicators

### 3. Technical Debt Log
- Document newly discovered technical debt
- Prioritize debt items (critical/high/medium/low)
- Plan debt resolution in next sprint

## Review Artifacts
- `docs/launch/weekly-review-results.md` - captured findings per review
- `docs/launch/technical-debt-log.md` - accumulating technical debt items
- `AGENTS.md` - updated with current state and decisions

## Ritual Workflow
1. Every Monday: Team reviews previous week's metrics and feedback
2. Capture findings in `docs/launch/weekly-review-results.md`
3. Update `docs/launch/technical-debt-log.md`
4. Define next sprint's top 3 items
5. Sync with team and update project board
